  <behavior>
CatalogService queries innovation_records via Knex, returning CatalogCard projections only (NOT full record — this is a performance-optimized projection). It joins record_tags for mission_area_tags and technology_area_tags, and fetches engagement_options from record_engagement_options.

**CatalogCard shape (implement exactly per FRD F00):**
```typescript
interface CatalogCard {
  record_id: string;
  title: string;
  short_summary: string;           // ≤ 280 chars from DB
  maturity_level: string;
  maturity_label: string;          // derived: maturityLabels[maturity_level]
  review_status: string;
  review_status_label: string;     // derived: reviewStatusLabels[review_status]
  mission_area_tags: string[];     // from record_tags WHERE tag_type='MISSION_AREA'
  technology_area_tags: string[];  // from record_tags WHERE tag_type='TECHNOLOGY_AREA'
  engagement_options: string[];    // option_type values from record_engagement_options
  source_type: string;
  reuse_potential: string;
  published_at: string;
  record_url: string;              // '/records/' + record_id
}
```

**Maturity label map (exact strings per FRD — copy verbatim):**
- IDEA → "Idea"
- EXPERIMENT_POC → "Experiment / POC"
- PROTOTYPE_PILOT → "Prototype / Pilot"
- PRODUCTION_VALIDATED → "Production / Validated Pattern"
- ARCHIVED → "Archived"

**Review status label map (exact strings per FRD — copy verbatim):**
- SUBMITTED → "Submitted"
- CURATED → "Curated"
- TECHNICALLY_REVIEWED → "Technically Reviewed"
- SECURITY_REVIEWED → "Security Reviewed"
- POLICY_REVIEWED → "Policy Reviewed"
- VALIDATED_FOR_REUSE → "Validated for Reuse"
- SUPERSEDED_RETIRED → "Superseded / Retired"

**Scope filtering (implement exactly):**
- PUBLIC scope: WHERE publication_state = 'PUBLISHED' only
  - SUPERSEDED and ARCHIVED records excluded (they have publication_state != 'PUBLISHED')
- CURATOR scope: all publication states visible; include state label on each card

**Multi-value filter application (all filters are AND conditions):**
- maturity_level[]: `.whereIn('ir.maturity_level', validValues)`
- review_status[]: `.whereIn('ir.review_status', validValues)` (NOTE: review_status is a VARCHAR column; not an array — each record has exactly one review_status at time of publication snapshot)
- contributing_office[]: `.whereIn('ir.contributing_office', validValues)`
- reuse_potential (single value): `.where('ir.reuse_potential', value)`
- mission_area[] and technology_area[]: filter via EXISTS subquery on record_tags

**Invalid enum filter values: silently ignore** — strip any value not in the allowed enum set before building the query. Do not 400; do not 500.

**Allowed enum values (use these sets for validation):**
```typescript
const VALID_MATURITY = ['IDEA','EXPERIMENT_POC','PROTOTYPE_PILOT','PRODUCTION_VALIDATED','ARCHIVED'];
const VALID_REVIEW = ['SUBMITTED','CURATED','TECHNICALLY_REVIEWED','SECURITY_REVIEWED','POLICY_REVIEWED','VALIDATED_FOR_REUSE','SUPERSEDED_RETIRED'];
const VALID_REUSE = ['HIGH','MEDIUM','LOW'];
```

**Sort orders (implement exactly per FRD F00):**
- `recent` (default): `ORDER BY ir.published_at DESC`
- `maturity`: `ORDER BY ARRAY_POSITION(ARRAY['PRODUCTION_VALIDATED','PROTOTYPE_PILOT','EXPERIMENT_POC','IDEA','ARCHIVED'], ir.maturity_level::text)`
  — Use `db.raw("ARRAY_POSITION(ARRAY['PRODUCTION_VALIDATED','PROTOTYPE_PILOT','EXPERIMENT_POC','IDEA','ARCHIVED'], ir.maturity_level::text)")` for Knex
- `relevance`: falls back to `recent` in pure catalog (no `q` param) — same as `ORDER BY published_at DESC`
- Unknown sort value: falls back to `recent`

**Pagination:**
- `page` non-integer or < 1: reset to 1
- `page_size` outside 1–50: clamp to range (min 1, max 50, default 12)
- LIMIT = page_size, OFFSET = (page - 1) * page_size
- Return: { total (COUNT), page, page_size, pages: Math.ceil(total/page_size), records }

**getFilters(scope):**
Returns distinct non-null values for each filter dimension from innovation_records (filtered by scope). For mission_areas and technology_areas, unnest from record_tags. Example:
```typescript
const maturityLevels = await db('innovation_records')
  .where({ publication_state: 'PUBLISHED' })
  .distinct('maturity_level')
  .whereNotNull('maturity_level')
  .pluck('maturity_level');
```
Tag-based facets unnest from record_tags via JOIN:
```typescript
const missionAreas = await db('record_tags as rt')
  .join('innovation_records as ir', 'rt.record_id', 'ir.id')
  .where('ir.publication_state', 'PUBLISHED')
  .where('rt.tag_type', 'MISSION_AREA')
  .distinct('rt.tag_value')
  .pluck('tag_value');
```

The core getCatalog query structure (Knex):
```typescript
let query = db('innovation_records as ir')
  .select(
    'ir.id as record_id',
    'ir.title',
    'ir.short_summary',
    'ir.maturity_level',
    'ir.review_status',
    'ir.source_type',
    'ir.reuse_potential',
    'ir.contributing_office',
    'ir.published_at'
  )
  .where('ir.publication_state', 'PUBLISHED');  // PUBLIC scope

// Apply maturity_level filter
if (filters.maturity_level?.length) {
  const valid = filters.maturity_level.filter(v => VALID_MATURITY.includes(v));
  if (valid.length) query = query.whereIn('ir.maturity_level', valid);
}

// Apply sort
if (sort === 'maturity') {
  query = query.orderByRaw(
    "ARRAY_POSITION(ARRAY['PRODUCTION_VALIDATED','PROTOTYPE_PILOT','EXPERIMENT_POC','IDEA','ARCHIVED'], ir.maturity_level::text)"
  );
} else {
  query = query.orderBy('ir.published_at', 'desc');
}

// Pagination
const safePageSize = Math.min(Math.max(pageSize, 1), 50);
const safePage = Math.max(page, 1);
const offset = (safePage - 1) * safePageSize;
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted query params (filter arrays, sort, page, page_size) crossing into DB query builder |
| db→API | innovation_records rows cross from DB into JSON response — scope filter must exclude non-PUBLISHED for PUBLIC callers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering (SQL injection) | GET /api/v1/catalog — filter array values piped into Knex `.whereIn()` | mitigate | All filter values pass through enum allowlist validation in `src/services/catalog.ts::getCatalog` before reaching Knex — only whitelisted enum strings enter `.whereIn()`; Knex uses parameterized bindings for all values; `orderByRaw` uses a static SQL literal with no user input interpolated |
| T-04-02 | Information disclosure | GET /api/v1/catalog — DRAFT/REVIEW/SUPERSEDED/ARCHIVED records exposed to PUBLIC caller | mitigate | `src/services/catalog.ts::getCatalog` enforces `WHERE publication_state = 'PUBLISHED'` for PUBLIC scope via Knex `.where('ir.publication_state', 'PUBLISHED')` — no dynamic interpolation; enforced at service layer, not just route layer |
| T-04-03 | Denial of service | GET /api/v1/catalog — unbounded page_size (attacker requests page_size=999999) | mitigate | `src/routes/api/catalog.ts` parses page_size and clamps to 1–50 before passing to service; `src/services/catalog.ts` applies `Math.min(Math.max(pageSize, 1), 50)` as double enforcement — upper bound is 50 rows maximum per response |
| T-04-04 | Denial of service | GET /api/v1/catalog/filters — full table scan on large dataset | accept | This is a Judiciary intranet application with <100 records at MVP scale. No caching needed now. Rate limiting deferred to Phase 5. Risk accepted by TSIO I&R team. |
| T-04-05 | Tampering | ARRAY_POSITION sort expression in orderByRaw | mitigate | `orderByRaw` in `src/services/catalog.ts::getCatalog` uses a static SQL string literal with no user-supplied values interpolated — the array contents are hardcoded enum strings, not derived from request params |
</threat_model>
