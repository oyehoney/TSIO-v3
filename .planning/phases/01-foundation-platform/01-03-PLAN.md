**src/auth/passport.ts** — OIDC strategy using passport-openidconnect. On callback: look up user by `profile.id` (maps to `idp_subject` = `sub` claim from OIDC). If user does not exist in the users table, create with role=CURATOR (default per TechArch schema). If user is not active (`is_active=false`), reject login.

```typescript
import passport from 'passport';
import { Strategy as OIDCStrategy, Profile } from 'passport-openidconnect';
import { config } from '../config/env';
import { db } from '../db/knex';
import type { UserSession } from './session';

export function configurePassport(): void {
  passport.use(
    'oidc',
    new OIDCStrategy(
      {
        issuer: config.OIDC_ISSUER_URL,
        authorizationURL: `${config.OIDC_ISSUER_URL}/oauth2/v2.0/authorize`,
        tokenURL: `${config.OIDC_ISSUER_URL}/oauth2/v2.0/token`,
        userInfoURL: `${config.OIDC_ISSUER_URL}/oidc/userinfo`,
        clientID: config.OIDC_CLIENT_ID,
        clientSecret: config.OIDC_CLIENT_SECRET,
        callbackURL: config.OIDC_REDIRECT_URI,
        scope: ['openid', 'profile', 'email'],
        // COMP-02: passport-openidconnect uses the system's TLS stack (OpenSSL)
        // which respects NODE_OPTIONS=--enable-fips in production
      },
      async (
        _issuer: string,
        profile: Profile,
        done: (err: Error | null, user?: UserSession | false) => void
      ) => {
        try {
          // idp_subject = OIDC sub claim
          const idpSubject = profile.id;
          const email = (profile.emails?.[0]?.value ?? '').toLowerCase();
          const displayName = profile.displayName ?? email;

          if (!idpSubject || !email) {
            return done(null, false);
          }

          // Upsert: insert on first login, update last_login_at on subsequent logins
          const existing = await db('users')
            .where({ idp_subject: idpSubject })
            .first<{ id: string; role: 'CURATOR' | 'ADMIN'; is_active: boolean; email: string; display_name: string }>();

          if (existing) {
            if (!existing.is_active) {
              // PLAT-01: deactivated users cannot log in
              return done(null, false);
            }
            await db('users')
              .where({ id: existing.id })
              .update({ last_login_at: db.fn.now(), updated_at: db.fn.now() });

            return done(null, {
              userId: existing.id,
              email: existing.email,
              displayName: existing.display_name,
              role: existing.role,
            });
          }

          // First login — create CURATOR account
          const [newUser] = await db('users')
            .insert({
              idp_subject: idpSubject,
              email,
              display_name: displayName,
              role: 'CURATOR',    // default per TechArch schema
              is_active: true,
              last_login_at: db.fn.now(),
            })
            .returning(['id', 'role', 'email', 'display_name']);

          return done(null, {
            userId: newUser.id,
            email: newUser.email,
            displayName: newUser.display_name,
            role: newUser.role,
          });
        } catch (err) {
          return done(err as Error);
        }
      }
    )
  );

  // Serialize/deserialize: store entire UserSession in session (small object, HMAC-protected)
  passport.serializeUser((user, done) => {
    done(null, user as UserSession);
  });

  passport.deserializeUser((user: UserSession, done) => {
    done(null, user);
  });
}
```

**src/middleware/auth.ts** — Role enforcement middleware:
```typescript
import { Request, Response, NextFunction, RequestHandler } from 'express';
import type { UserSession } from '../auth/session';

/**
 * requireAuth — PLAT-01 enforcement.
 * Returns 401 JSON if no valid session. Use on any protected route.
 */
export function requireAuth(req: Request, res: Response, next: NextFunction): void {
  if (!req.session.user) {
    res.status(401).json({ error: 'Authentication required' });
    return;
  }
  next();
}

/**
 * requireRole — PLAT-01 role enforcement.
 * Must be used AFTER requireAuth (assumes session.user exists).
 * Returns 403 if the authenticated user's role does not satisfy the requirement.
 *
 * Role hierarchy: ADMIN > CURATOR
 * requireRole('CURATOR') → allows CURATOR and ADMIN
 * requireRole('ADMIN')   → allows ADMIN only
 */
export function requireRole(minimumRole: 'CURATOR' | 'ADMIN'): RequestHandler {
  return (req: Request, res: Response, next: NextFunction): void => {
    const user = req.session.user as UserSession | undefined;
    if (!user) {
      res.status(401).json({ error: 'Authentication required' });
      return;
    }
    if (minimumRole === 'ADMIN' && user.role !== 'ADMIN') {
      res.status(403).json({ error: 'Insufficient permissions' });
      return;
    }
    // minimumRole === 'CURATOR' allows CURATOR or ADMIN
    next();
  };
}
```

**src/routes/auth.ts** — TechArch API spec:
```
POST /auth/login      → redirect to OIDC provider
GET  /auth/callback   → OIDC callback, create/update user row, set session
POST /auth/logout     → destroy session
GET  /auth/me         → return UserSession or 401
```

```typescript
import { Router } from 'express';
import passport from 'passport';
import { requireAuth } from '../middleware/auth';
import type { UserSession } from '../auth/session';

export const authRouter = Router();

/**
 * POST /auth/login — redirect to Azure AD OIDC provider.
 * TechArch: POST /auth/login → redirect to OIDC provider
 */
authRouter.get('/login', passport.authenticate('oidc'));

// Also accept POST for form-based triggers
authRouter.post('/login', passport.authenticate('oidc'));

/**
 * GET /auth/callback — OIDC callback from Azure AD.
 * TechArch: GET /auth/callback → OIDC callback, create/update user row, set session
 * On success: set req.session.user and redirect to /admin or referer.
 * On failure: redirect to / with error query param.
 */
authRouter.get(
  '/callback',
  passport.authenticate('oidc', { failureRedirect: '/?error=auth_failed' }),
  (req, res) => {
    // Passport sets req.user after successful authentication
    // Copy to session for consistent access throughout the app
    if (req.user) {
      req.session.user = req.user as UserSession;
    }
    // Redirect to admin for authenticated users
    res.redirect('/admin');
  }
);

/**
 * POST /auth/logout — destroy session.
 * TechArch: POST /auth/logout → destroy session
 */
authRouter.post('/logout', (req, res, next) => {
  req.session.destroy((err) => {
    if (err) {
      return next(err);
    }
    res.clearCookie('connect.sid');
    res.redirect('/');
  });
});

/**
 * GET /auth/me — return UserSession or 401.
 * TechArch: GET /auth/me → return UserSession or 401
 */
authRouter.get('/me', requireAuth, (req, res) => {
  // requireAuth guarantees session.user exists
  res.json(req.session.user as UserSession);
});
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | All auth endpoints receive unauthenticated HTTP requests; OIDC callback receives attacker-controlled query parameters |
| OIDC provider→callback | Azure AD redirects back with authorization code; the code is exchanged via back-channel (server-to-server) — not exposed to client |
| session→handler | Session data crosses from cookie/store into request handlers; must be treated as untrusted until validated by requireAuth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | OIDC callback forgery (CSRF on /auth/callback) | mitigate | passport-openidconnect uses state parameter (nonce) stored in session; mismatched state causes `failureRedirect`. Verified by: `grep -n 'state\|nonce' node_modules/passport-openidconnect/lib/strategy.js` — the library generates state automatically. |
| T-03-02 | Elevation of privilege | OIDC profile injection — attacker-supplied profile.id creates ADMIN user | mitigate | New users created with role='CURATOR' (hardcoded default, never from OIDC profile) in `src/auth/passport.ts` OIDC callback. Role escalation requires an ADMIN to update via Plan 05 settings UI. Verified by: `grep -n "role: 'CURATOR'" src/auth/passport.ts`. |
| T-03-03 | Elevation of privilege | Deactivated user bypasses is_active check | mitigate | `src/auth/passport.ts` OIDC callback checks `existing.is_active`; returns `done(null, false)` (blocks login) when false. Passport then invokes failureRedirect. Verified by: `grep -n 'is_active' src/auth/passport.ts`. |
| T-03-04 | Information disclosure | Session fixation — attacker pre-sets session ID before auth | mitigate | express-session regenerates session ID on `req.session.regenerate()`. Add explicit `req.session.regenerate()` call in /auth/callback before setting `req.session.user` to prevent fixation. Verified by: `grep -n 'regenerate' src/routes/auth.ts`. |
| T-03-05 | Information disclosure | UserSession leaks PII to logs | mitigate | Winston logger must NOT log `req.session` or `req.user` objects. Enforced by logger configuration: serialize only `req.method`, `req.path`, `res.statusCode` (no user object). Pattern check: `grep -rn 'req\.session\|req\.user' src/middleware/` must return only auth.ts requireAuth (no console.log calls). |
| T-03-06 | Tampering | OIDC email claim used as identity (email is mutable in Azure AD) | mitigate | `idp_subject` (`sub` claim) is the identity anchor in the users table — immutable per OIDC spec. Email is stored for display only and updated on each login. Verified by: `grep -n 'idp_subject: idpSubject\|idp_subject.*profile' src/auth/passport.ts`. |
| T-03-07 | Denial of service | Logout without session causes error cascade | mitigate | `POST /auth/logout` calls `req.session.destroy()` which succeeds even if session is empty. `clearCookie` is idempotent. Error path calls `next(err)` for Express error handler — no crash. |
</threat_model>
