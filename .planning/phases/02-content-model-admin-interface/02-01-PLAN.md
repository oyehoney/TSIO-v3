<feature>
  <name>PublicationLifecycleService — state machine enforcement</name>
  <files>src/services/publication-lifecycle.ts, tests/publication-lifecycle.test.ts</files>
  <behavior>
PublicationLifecycleService.transition(recordId, targetState, userId, meta?) enforces the exact state machine from FRD F8.

VALID transitions (ONLY these are valid — any other is INVALID_STATE_TRANSITION 422):
- DRAFT → REVIEW  (submit-review action)
- REVIEW → PUBLISHED  (publish action — governance gate applied before this is called)
- REVIEW → DRAFT  (return-draft action)
- PUBLISHED → REVIEW  (edit action — requires confirmation, handled at route layer)
- PUBLISHED → SUPERSEDED  (supersede action — requires meta.superseded_by_record_id)
- PUBLISHED → ARCHIVED  (archive action)
- SUPERSEDED → ARCHIVED  (archive action)

All other transitions (e.g. DRAFT→PUBLISHED, ARCHIVED→anything, SUPERSEDED→PUBLISHED) → throw PublicationLifecycleError with code INVALID_STATE_TRANSITION.

PUBLISHED→SUPERSEDED: if meta.superseded_by_record_id is missing → throw PublicationLifecycleError with code SUPERSEDE_REQUIRES_SUCCESSOR.

On successful transition:
- Update innovation_records.publication_state to targetState
- If targetState === 'PUBLISHED': set published_at = NOW()
- If targetState === 'SUPERSEDED': set superseded_by_record_id = meta.superseded_by_record_id
- Call auditService.log('innovation_records', recordId, 'STATE_TRANSITION', userId, { publication_state: fromState }, { publication_state: targetState })

Test cases:
- DRAFT → REVIEW → succeeds, publication_state = 'REVIEW'
- REVIEW → PUBLISHED → succeeds (governance gate pre-checked by caller), published_at set
- REVIEW → DRAFT → succeeds
- PUBLISHED → REVIEW → succeeds
- PUBLISHED → SUPERSEDED with superseded_by_record_id → succeeds, superseded_by_record_id set
- PUBLISHED → SUPERSEDED without superseded_by_record_id → throws SUPERSEDE_REQUIRES_SUCCESSOR
- PUBLISHED → ARCHIVED → succeeds
- SUPERSEDED → ARCHIVED → succeeds
- DRAFT → PUBLISHED → throws INVALID_STATE_TRANSITION
- ARCHIVED → DRAFT → throws INVALID_STATE_TRANSITION
- ARCHIVED → REVIEW → throws INVALID_STATE_TRANSITION
  </behavior>
  <implementation>
Export VALID_TRANSITIONS map and PublicationLifecycleService class. The service reads the record's current publication_state from the DB, checks it against VALID_TRANSITIONS[currentState], throws on invalid. Uses RecordRepository to perform the UPDATE. Calls AuditService.log for every transition. PublicationLifecycleError class with code field (INVALID_STATE_TRANSITION | SUPERSEDE_REQUIRES_SUCCESSOR) — route handler catches this and maps to 422.
  </implementation>
</feature>
