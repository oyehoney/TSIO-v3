## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| db→render | innovation_records rows fetched from DB and rendered into EJS list template — stored XSS if title/owner fields are not escaped |
| client→API | Delete button sends DELETE /api/v1/admin/records/:id — :id from DOM, not validated at UI layer (validation done in API layer from 02-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Information disclosure | GET /admin/records + GET /admin/dashboard — page routes expose record inventory to authenticated curator | mitigate | requireAuth + requireRole('CURATOR') in `src/routes/admin/record-pages.ts` before both handlers; RecordService.listRecords('CURATOR') applies `WHERE deleted_at IS NULL` scope — soft-deleted records never appear in list |
| T-02-13 | Tampering (stored XSS) | EJS list.html renders record title, owner_name, contributing_office from DB into HTML | mitigate | All EJS output uses `<%=` (auto-escaped) in `src/views/admin/records/list.html` — never `<%-` for user-controlled fields; verified by grep in verification step |
| T-02-14 | Elevation of privilege | GET /admin/content-model-reference — static reference page, no secrets, but still admin-only UI | mitigate | requireAuth + requireRole('CURATOR') in `src/routes/admin/record-pages.ts` — no unauthenticated access to admin area even for read-only pages |
| T-02-15 | Repudiation | Delete button fires DELETE from browser JS — no CSRF token on API delete | accept | All admin API routes require an active express-session (requireAuth from Phase 1); express-session cookies are httpOnly + sameSite=Strict (set in Phase 1 01-01 app.ts), which provides same-site CSRF protection equivalent. Accepted: no third-party origin can trigger the delete; insider-threat deletion is captured in AuditService (T-02-06 from 02-01). |
</threat_model>
