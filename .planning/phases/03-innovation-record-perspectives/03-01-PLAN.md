## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Unauthenticated request supplying :record_id path param — untrusted UUID crosses into DB query |
| db→API | innovation_records row including publication_state crosses from DB into response — scope filter must be enforced before serialization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information disclosure | GET /api/v1/records/:record_id — non-PUBLISHED record accessible to PUBLIC caller | mitigate | Scope check enforced in `src/routes/api/records.ts`: when session absent or role === 'PUBLIC', calls `recordService.getRecord(id, 'PUBLIC')` which delegates to `RecordRepository.findById(id, 'PUBLIC')` applying `WHERE publication_state = 'PUBLISHED' AND deleted_at IS NULL` — returns null → 404 before any field is serialized |
| T-03-02 | Tampering | GET /api/v1/records/:record_id — :record_id from URL path piped into DB query | mitigate | Knex parameterized query in `src/repositories/record-repository.ts::findById` — record_id is bound as a query parameter, never string-interpolated; non-existent UUIDs return null → 404 |
| T-03-03 | Tampering | trust_disclaimers computed from DB fields — a curator editing source_type or review_status could affect disclaimer output | accept | Disclaimer computation is system-derived and non-suppressible — no curator action can suppress disclaimers, only trigger more. Accepted: changing source_type/review_status is an authorized curator action and the resulting disclaimer change is correct behavior. AuditService (from 02-01) captures field edits. |
| T-03-04 | Denial of service | GET /api/v1/records/:record_id — public unauthenticated endpoint; no rate limiting | accept | Public read-only endpoint for a Judiciary intranet application; unauthenticated traffic is low-risk. Rate limiting deferred to Phase 5 (F5 submission forms are the higher-risk surface). Accepted: no user data exposed, no mutations; DoS risk is operational, not data-integrity. |
</threat_model>
